# 🤖 Бот-напоминалка для Telegram

Telegram-бот, который **запоминает важные даты** и **напоминает о них**, позволяет
добавлять пользователей **в друзья по @username**, делиться своими датами и вести
общий **вишлист**, чтобы друзья могли заранее узнать, что тебе приятно получить
в подарок.

Бот периодически (раз в день, по расписанию) рассылает всем пользователям
напоминания вида:

```
⏰ Напоминание!
«др у мамы» — 19 сентября (через 3 дн.).
```

```
👫 Ближайшие даты у друзей:
• @alice — «др у мамы» · через 2 дня
• @alice — «сессия» · через 2 дня
🎁 Вишлист @alice:
   Наушники
   Книга
```

## Возможности

| Возможность | Описание |
|---|---|
| 📅 Запоминание дат | Добавляй события с названием и датой, бот хранит их и напоминает заранее |
| ⏰ Автонапоминания | За `3` дня до события (настраивается) пользователь получает личное напоминание |
| 👥 Друзья по @username | Заявка в друзья, принятие / отклонение, уведомления обеим сторонам |
| 📣 Общие даты | Друзья узнают о твоих ближайших датах (с указанием человеческого срока) |
| 🎁 Вишлисты | Каждый ведёт список желаемых подарков, друзья видят их кратко в уведомлениях |
| 🔎 Вишлист друга | Команда `/wishlist_friend @имя` показывает полный вишлист друга |
| 🔒 Без спама | Каждая комбинация «событие + получатель + срок» отправляется только один раз |
| 🗄 Лёгкое хранение | Вся история в одном SQLite-файле, без внешней БД |

### Примеры сообщений, которые отправляет бот

- Личное напоминание:
  `⏰ Напоминание! «др у мамы» — 17 сентября (через 2 дн.).`
- Уведомление при заявке в друзья:
  `🔔 @alice хочет добавить вас в друзья. Принять: /accept <id> | Отклонить: /decline <id>`
- Публичное уведомление другу о твоей дате (если у него несколько твоих дат — они группируются):
  `👫 Ближайшие даты у друзей: • @alice — «др у мамы» · через 2 дня … 🎁 Вишлист @alice: Наушники`

> **Почему упоминания дружеские:** бот никогда не шлёт «сырье» `@mention` чужим
> людям. Имена друзей показываются обычным текстом (`@alice`), чтобы из чата не
> «протекали» юзернеймы тех, кто не просил о публичности.

## Поддерживаемые команды

### События (даты)
| Команда | Действие |
|---|---|
| `/start` | Приветствие + главное меню |
| `/help` | То же, что `/start` |
| `/addevent <название> <дата>` | Добавить событие (дата может быть в разных форматах, см. ниже) |
| `/addevent` | Интерактивное добавление (бот спросит название и дату) |
| `/myevents` | Показать мои ближайшие и все даты |
| `/delevent <номер>` | Удалить дату (номер выдаёт `/myevents`) |

### Друзья
| Команда | Действие |
|---|---|
| `/friends` | Список друзей и входящих заявок |
| `/addfriend @username` | Отправить заявку в друзья |
| `/accept <id>` | Принять заявку |
| `/decline <id>` | Отклонить заявку |

### Вишлист
| Команда | Действие |
|---|---|
| `/wishlist` | Показать мой вишлист |
| `/addwish <текст>` | Добавить в вишлист |
| `/addwish` | Интерактивное добавление |
| `/delwish <номер>` | Удалить пункт из вишлиста |
| `/wishlist_friend @username` | Показать полный вишлист друга (только для взаимных друзей) |

### Управление диалогами
| Команда | Действие |
|---|---|
| `/cancel` | Прервать текущий многошаговый диалог |

## Принимаемые форматы дат

Бот понимает большое количество форматов (примеры, `дата` = 25 марта):

- `25.03.2026` — точка, полная дата
- `25/03/2026` — слэш
- `2026-03-25` — ISO
- `25.03` — без года (текущий год; если дата уже прошла — следующий)
- русские: `двадцать пятого марта`, `25 марта` и т.п.
- любые форматы, поддерживаемые библиотекой `python-dateutil`

> ⚠️ В прошлом даты не принимаются — бот попросит указать будущую.

## Установка и запуск

### Требования
- Python `3.10+`
- Токен бота от **@BotFather** в Telegram

### Шаги

```bash
# 1. Клонировать репозиторий
git clone https://github.com/moyslav/bot-tg-napominalka.git
cd bot-tg-napominalka

# 2. (рекомендуется) Создать виртуальное окружение
python -m venv .venv
source .venv/bin/activate        # Linux/macOS
# .venv\Scripts\activate          # Windows

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Настроить окружение
cp .env.example .env
# откройте .env и подставьте свой BOT_TOKEN

# 5. Запустить
python main.py
```

> Бот работает в режиме **polling** (сам опрашивает Telegram). Для использования
> в продакшене на выделенном сервере, возможно, захочется перейти на webhook —
> см. раздел «Деплой».

### Файл `.env`

```dotenv
# Обязательное
BOT_TOKEN=123456:your_token_here   # от @BotFather

# Необязательное
BOT_USERNAME=MyReminderBot          # имя бота (без @), для справки
DB_PATH=data/app.db                 # путь к файлу SQLite
SCHEDULER_TIMEZONE=Europe/Moscow    # IANA-таймзона для "сегодня" и расписания

# Networking (Telegram заблокирован напрямую — ходим через релей)
TELEGRAM_API_BASE_URL=https://tgproxy-plum.vercel.app/bot   # БЕЗ PROXY_URL
TELEGRAM_FILE_BASE_URL=
```

> 🔐 **Никогда не коммитьте настоящий токен.** В `.env` он уже добавлен в
> `.gitignore`. Вместо него в репозиторий коммитится `.env.example` с плейсхолдером.

### Обход блокировки Telegram (РФ) через релей

Если на хосте `api.telegram.org` недоступен напрямую (РФ-блокировка), не нужно
никаких VPN/SOCKS/MTProto-клиентов. Бот ходит на **релей Bot API** (развёрнут
на Vercel за пределами РФ), который проксирует `api.telegram.org`:

```dotenv
TELEGRAM_API_BASE_URL=https://tgproxy-plum.vercel.app/bot
```

URL строится как `<TELEGRAM_API_BASE_URL><TOKEN>/<method>`, поэтому значение
обязано заканчиваться на `/bot`. Проверка доступности:

```bash
curl -s https://tgproxy-plum.vercel.app/bot<TOKEN>/getMe
# -> {"ok":true,...}
```

Когда релей не нужен (прямой доступ к Telegram есть) — просто оставьте
`TELEGRAM_API_BASE_URL` пустым, бот пойдёт на `api.telegram.org` напрямую.
`services/network.py` собирает `HTTPXRequest` с таймаутами 60/70/70 с, щадящими
медленный старт serverless-релея. Не используйте локальные SOCKS/HTTP-прокси
(`PROXY_URL`) для этого бота — они не нужны и не помогут.

> Надёжность: `main.py` оборачивает polling в цикл с ретраями. Если связь с
> Telegram пропадёт (например, туннель временно отвалился «после 19:00»), бот не
> падает, а ждёт `RETRY_DELAY_SECONDS` (по умолчанию 30 с) и пробует снова.

## Конфигурация напоминаний

Параметры напоминаний задаются константами в `services/scheduler.py`:

| Константа | Значение | Смысл |
|---|---|---|
| `REMIND_DAYS` | `3` | За сколько дней до события начинаются напоминания |
| `DAILY_HOUR` | `9` (в `main.py`) | Час (24ч), в который раз в день запускается сканирование |

Если хочешь иные сроки — поменяй эти значения и перезапусти бота.

## Как работает напоминание (детали)

1. Раз в день в назначенный час **APScheduler** запускает `run_daily_reminders(bot)`.
2. Функция находит все события, у которых `event_date` попадает в окно
   от «сегодня» до «сегодня + `REMIND_DAYS`».
3. Для каждого владельца:
   - отправляется **личное** напоминание (если оно ещё не отправлялось для этого
     срока),
   - каждому принятому другу отправляется **уведомление** о чужих датах
     (события одного друга на один день группируются в одно сообщение, чтобы не
     спамить), плюс добавляется краткий **вишлист** друга.
4. Каждое отправленное уведомление фиксируется в таблице `event_notifications`.
   Благодаря уникальному ключу `(event_id, kind, days_out, sent_to_user)` одно и
   то же сочетание никогда не отправляется дважды, но новое (например, за `3` дня,
   а потом за `1` день) — отправляется.

Таким образом, функцию можно вызывать сколько угодно раз в день — она **идемпотентна**,
ничего не дублируя.

## База данных

Хранится в SQLite-файле (по умолчанию `data/app.db`). Схема создаётся автоматически
при первом запуске. Основные таблицы:

- **`users`** — пользователи бота (`user_id`, `username`, `full_name`).
- **`events`** — события/даты (`user_id`, `title`, `event_date`).
- **`friendships`** — дружбы и заявки (`requester_id`, `addressee_id`, `status`)
  со статусами `pending` / `accepted` / `declined`.
- **`wishlist_items`** — пункты вишлиста (`user_id`, `text`).
- **`event_notifications`** — журнал отправок для дедупликации.

Включена `PRAGMA foreign_keys = ON` — удаление пользователя каскадно чистит связанные
записи.

### Безопасность запросов

Все запросы, в которые попадает пользовательский ввод, используют **параметризованные
SQL-запросы** (`?`-плейсхолдеры), никогда не конкатенацию строк. Подробнее — в
`repos.py` и `db.py`. Это исключает SQL-инъекции.

## Тестирование

Есть автономный smoke-тест, который проверяет слой данных и логику планировщика без
доступа к Telegram (использует фальшивый бот-объект и временную БД):

```bash
python test_smoke.py
# ... SMOKE_OK
```

Он проверяет:
- создание дружбы и принятие заявки;
- корректность текстов напоминаний (включая «через N дня/дн.»);
- **идемпотентность**: повторный запуск планировщика не отправляет дублей.

## Деплой

Бот запускается как длительный процесс. Проще всего — под любым менеджером процессов:

**systemd (Linux)**
```ini
[Unit]
Description=Telegram reminder bot
After=network-online.target

[Service]
User=youruser
WorkingDirectory=/opt/bot-tg-napominalka
ExecStart=/opt/bot-tg-napominalka/.venv/bin/python main.py
Restart=always

[Install]
WantedBy=multi-user.target
```

**Docker (пример)**
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
CMD ["python", "main.py"]
```

Для production-нагрузки можно перевести бота на **webhook** (методы
`ApplicationBuilder` → `webhook_info`, `run_webhook`) — при необходимости.
